# Сэндбокс

Заготовка приложения для [zerotomvp](https://zerotomvp.xyz). Внутри —
React + Vite на фронте и [Hono](https://hono.dev) на сервере, одним процессом.

Всё, что здесь появится, принадлежит вам: репозиторий, собранный образ,
хостинг и домен — в ваших собственных аккаунтах. zerotomvp только связывает
их между собой и может отойти в сторону, ничего не забрав.

## Локальный запуск

Нужен Node 20.19+ и pnpm.

```bash
pnpm install
pnpm dev
```

Откроется http://localhost:5173. Фронт живёт на Vite, запросы к `/api`
проксируются в Hono на порту 3000.

## Как это выкатывается

Каждый push в `main` запускает GitHub Actions: приложение собирается здесь,
и если сборка сломана — это видно сразу, до всякого выката. Затем сборка
выкатывает себя сама, командой `railway up`.

Выкат идёт токеном, который платформа выдала **на один этот проект Railway**
и может отозвать. Ключей от остального вашего хостинга у репозитория нет.
Пока хостинг не подключён, сборка просто проходит и говорит об этом.

Образ собирается по вашему `Dockerfile` на стороне Railway. Так вышло не от
хорошей жизни: приватный реестр образов Railway разрешает только на плане Pro,
поэтому загрузка сборки — единственный путь, работающий на Hobby.

## Где он живёт

Приложение работает на вашем аккаунте в Railway и оплачивается по вашему
тарифу там же. До того как вы привяжете свой домен, сэндбокс доступен по
временному адресу, который выдаёт Railway; после привязки — по вашему домену
из Cloudflare, с сертификатом, который выпускает Railway.

## Что менять можно, а что лучше не трогать

Меняйте что угодно — это ваш репозиторий. Но платформа рассчитывает на три
вещи, и без них сэндбокс не поднимется:

| Что | Зачем |
|---|---|
| `Dockerfile` в корне | по нему собирается образ |
| приложение слушает порт из `PORT` | платформа сама назначает порт |
| `GET /healthz` отвечает успехом, когда приложение готово | по нему платформа решает, можно ли пускать трафик |

Хранилище платформа передаёт переменными окружения — приложение их только
читает:

| Переменная | Что это |
|---|---|
| `SUPABASE_URL` | адрес вашего проекта Supabase |
| `SUPABASE_SECRET_KEY` | серверный ключ; в клиентский бандл попадать не должен |
| `SUPABASE_BUCKET` | бакет, заведённый для этого сэндбокса |

`GET /health/storage` показывает, дошли ли эти переменные до работающего
приложения и отвечает ли бакет. Без настроек эндпоинт не падает, а честно
сообщает, что хранилище не подключено.

Если удалить workflow из `.github/workflows`, сборка перестанет запускаться и
сэндбокс останется на последней собранной версии.
