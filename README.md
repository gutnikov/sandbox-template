# Сэндбокс

Заготовка приложения для [zerotomvp](https://zerotomvp.xyz). Внутри —
React + Vite на фронте и [Hono](https://hono.dev) на сервере, одним процессом.

Адрес вашего сэндбокса: `https://<имя-репозитория>.zerotomvp.xyz`

## Локальный запуск

Нужен Node 20.19+ и pnpm.

```bash
pnpm install
pnpm dev
```

Откроется http://localhost:5173. Фронт живёт на Vite, запросы к `/api`
проксируются в Hono на порту 3000.

## Как это выкатывается

Каждый push в `main` запускает сборку в GitHub Actions: собирается образ по
`Dockerfile` и публикуется в реестр платформы. Секреты для этого не нужны —
сборка предъявляет платформе удостоверение, которое GitHub выдаёт самому
запуску.

## Сэндбокс засыпает

Сервер платформы небольшой, поэтому сэндбокс не держится запущенным
постоянно: он останавливается после получаса работы и поднимается заново
при следующем обращении к адресу. Первое открытие после сна занимает
несколько секунд — страница сама переключится на приложение.

Одновременно запущено ограниченное число сэндбоксов. Если мест не хватает,
останавливается тот, к которому дольше всех не обращались; на следующем
заходе он поднимется снова.

## Что менять можно, а что лучше не трогать

Меняйте что угодно — это ваш репозиторий. Но платформа рассчитывает на три
вещи, и без них сэндбокс не поднимется:

| Что | Зачем |
|---|---|
| `Dockerfile` в корне | по нему собирается образ |
| приложение слушает порт из `PORT` | платформа сама назначает порт |
| `GET /healthz` отвечает успехом, когда приложение готово | по нему платформа решает, можно ли пускать трафик |

Если удалить workflow из `.github/workflows`, сборка перестанет запускаться и
сэндбокс останется на последней собранной версии.

